## Runtime configuration

Nothing is baked into the bundle. `ltAngularRequestHandler()` in `server.ts` reads the `NG_*` environment on every
request into a request context (`REQUEST_CONTEXT` in the app) and writes the public part as
`<script id="ng-runtime-config">` into every HTML response, client-rendered routes included. The browser reads that
script, so one image runs on every stage. In code, read it through `inject(LT_RUNTIME_CONFIG)`.

| Variable                                                              | Scope                 | Purpose                                                                                                                             |
| --------------------------------------------------------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `NG_PUBLIC_API_URL`                                                   | browser, SSR fallback | Public API URL                                                                                                                      |
| `NG_API_URL`                                                          | SSR only              | Internal API URL for server-side requests, never sent to the browser                                                                |
| `NG_PUBLIC_SITE_URL`                                                  | public                | App URL for redirect and callback URLs, SEO, `security.txt`                                                                         |
| `NG_PUBLIC_API_PROXY`                                                 | browser               | `true`: browser calls go to `/api/*` (dev proxy or `ltApiProxy()`); unset: on in dev mode, with a warning                           |
| `NG_PUBLIC_COOKIE_PREFIX`                                             | public                | Cookie namespace (`<prefix>-auth-state`), the same as the backend's `COOKIE_PREFIX`                                                 |
| `NG_PUBLIC_STORAGE_PREFIX`                                            | public                | `localStorage` prefix of `LtStorageService`                                                                                         |
| `NG_PUBLIC_LT_<FEATURE>_<OPTION>`                                     | public                | Feature options, e.g. `NG_PUBLIC_LT_TUS_DEFAULT_ENDPOINT`, `NG_PUBLIC_LT_AUTH_LOGIN_PATH`, `NG_PUBLIC_LT_AUTH_SYSTEM_SETUP_ENABLED` |
| `NG_LT_SECURITY_TXT_*`                                                | server                | `CONTACT`, `HOSTS`, `POLICY`, `PREFERRED_LANGUAGES`, `VALID_DAYS`                                                                   |
| `NG_PUBLIC_APP_COMMIT`, `APP_VERSION_COMMIT`, `NG_PUBLIC_APP_VERSION` | server                | Build identity                                                                                                                      |

The bug reporter has its own variables, see [Bug reporting](./6.bug-reporting.md).

Never read `process.env` in app code, and do not add Angular `environment.ts` files for API URLs.

## Without SSR

For static hosting or a backend other than the app's own server, pass the values in code:

```ts
provideLtNgBase({ runtime: { apiUrl: 'https://api.example.com' } });
```

## Texts (de/en)

Library texts come in German and English, chosen by the browser language, by `LtI18nService.setLocale()` or by an app
i18n library bound through `LT_I18N_ADAPTER` (Transloco, ngx-translate).

- Every entry point brings its own keys and registers them on first use. The initial bundle carries only the core's
  `lt.error.*`; `lt.ui.*`, `lt.auth.*`, `lt.files.*`, `lt.share.*` and `lt.bug.*` follow with their entry points.
- The same texts ship as JSON for the app's translation files: `i18n/{de,en}.json` (core) and
  `i18n/<entry>/{de,en}.json`.
- App texts always win: `provideLtNgBase({ i18n: { messages } })`, `registerMessages()` or the adapter override any key.
