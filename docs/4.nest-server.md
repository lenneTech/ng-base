## API URLs

`LtApiUrlService` knows two URLs:

- **`buildUrl(path)`** is for requests. During SSR it returns the internal `NG_API_URL` (for example `http://api:3000`),
  in the browser the public URL or `/api` behind the proxy.
- **`buildBrowserUrl(path)`** is for everything that ends up in the page: `src`, `href`, `srcset`, `poster`, CSS
  `url()`, meta tags. It uses `NG_PUBLIC_API_URL` (or `/api`) on the server too.

A URL from `buildUrl()` in the HTML points to a host the browser cannot reach. File URLs come from
`LtFileService.getFileUrl()` / `getDownloadUrl()`, which use the public URL as well.

## Requests

- `HttpClient`: add `ltAuthInterceptor` (`provideHttpClient(withInterceptors([ltAuthInterceptor]))`).
- `fetch`: use `inject(LT_FETCH)`, which adds the cookie or JWT handling and renews a JWT that is about to expire.

## SSR: backend calls are anonymous

During SSR every API call of ng-base goes out **without** the user's session: `LT_FETCH`, `ltAuthInterceptor`, the AI
services and offline sync. The server reads the auth state from the `lt-auth-state` cookie only to decide what to
render, and never reads `lt-jwt-token`. The session cookie belongs to the API host anyway, so the app server usually
never receives it.

For pages that show user data:

- **Load it in the browser**, for example in `afterNextRender()` or in a resource that only starts when
  `isPlatformBrowser(…)`, with a skeleton for the first paint. `resource()` and `httpResource()` run during SSR too.
- **Render only public data on the server**, and never decide access there.
- A page that truly needs user data in the SSR HTML needs a route of the app's own server that forwards the request's
  session to the API, set up per project with a shared cookie domain. ng-base does not do that.

This also means no cached route can serve one user's data to the next.

## Error codes

nest-server marks its error messages with codes such as `#LTNS_0023:`. Show them through `LtErrorTranslationService`:

```ts
private readonly errors = inject(LtErrorTranslationService);

this.errors.translateError(error); // German or English text for the code
this.errors.showErrorToast(error, 'Speichern fehlgeschlagen');
```

## File uploads (TUS)

nest-server receives uploads on `/tus` and stores them as files. `injectLtTusUpload()` creates an upload queue bound to
the component; running uploads stop when the component is destroyed.

```ts
protected readonly upload = injectLtTusUpload({ onSuccess: (item) => this.attach(item.fileId) });
```

- `tus-js-client` is an optional peer and loads lazily; without it `addFiles` rejects with an install hint.
- Defaults: automatic start, three parallel uploads, retries, resume, the session cookie or the JWT, and the stored
  file's id from the `X-File-Id` header.
- `<lt-tus-upload>` from `@lenne.tech/ng-base/files/ui` is the ready-made upload component.
- `LtFileService` resolves file and download URLs, reads file info and formats sizes.

Change the endpoint or chunk size with `provideLtFiles({ tus: { … } })` or `NG_PUBLIC_LT_TUS_*`.

## AI

The AI module of nest-server (`/ai`) is available through `@lenne.tech/ng-base/ai`:

- `injectLtAiChat()` creates a chat with its own state (messages, conversation, budget), streamed by default. It stops
  when the component is destroyed.
- `LtAiStatusService` tells whether the API runs the AI module (`GET /ai/status`), so an app can hide its AI pages.
- Services for connections, settings, usage, prompts, placeholders and the admin pages.

```ts
protected readonly chat = injectLtAiChat({ connectionId: this.connectionId });
```

`provideLtAi({ basePath })` is only needed when the API mounts the module elsewhere.

## Offline sync

`injectLtOfflineSync()` keeps the records of one model in IndexedDB. Changes made offline wait in an outbox and go out
with the next sync; nest-server's sync protocol and a hint stream keep tabs and devices up to date.

```ts
export class NotesPage {
  protected readonly notes = injectLtOfflineSync<{ title: string }>('note');

  add(title: string) {
    return this.notes.create({ title });
  }
}
// template: @for (note of notes.records(); track note.id) { … } · notes.pendingCount() · notes.offline()
```

- Needs `provideLtSync()` and `provideLtAuth()`.
- The local data belongs to the signed-in user: another user's data is wiped before anything is shown. `signOut()` sends
  what is unsent and then deletes it; an expired session deletes nothing.
- During SSR or without IndexedDB it is an inert stub.
