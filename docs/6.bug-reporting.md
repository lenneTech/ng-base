`@lenne.tech/ng-base/bug` is the Angular counterpart of [`@lenne.tech/bug.lt`](https://github.com/lenneTech/bug.lt). A
floating button takes a screenshot; the dialog collects title, type, description, steps and attachments, plus console
output, network requests, the user's path through the app and browser details. The app's own SSR server creates the
Linear issue.

## Setup

```ts
// app.config.ts
import { provideLtBug } from '@lenne.tech/ng-base/bug/provide';
provideLtBug({ autoOpenOnError: true }),

// app.ts (imports: [LtBugReport] from '@lenne.tech/ng-base/bug')
protected readonly bugActive = inject(LT_BUG_ACTIVE); // from '@lenne.tech/ng-base/bug/provide'
```

```html
<!-- app.html: loaded only where the reporter is on; it starts capturing right after the first render -->
@if (bugActive) { @defer (on immediate) { <lt-bug-report /> } }
```

```ts
// server.ts, before express.json() and the Angular handler
app.use(ltBugReport()); // POST /_bug-lt/report
```

Server environment, never sent to the browser: `NG_LINEAR_API_KEY`, `NG_LINEAR_TEAM_NAME` (name or key),
`NG_LINEAR_PROJECT_NAME` (optional). Screenshots need the optional peer `modern-screenshot`; without it the screenshot is
skipped. With `core.css` instead of `theme.css`, add `components/lt-bug-report.css`.

Only `@lenne.tech/ng-base/bug/provide` (about 1 kB) is in the initial bundle. Production loads nothing else; on the other
stages the button, the capture, the dialog and the texts load when needed.

## When it is on

It is off in production, decided at runtime per stage:

- The browser reads `NG_PUBLIC_APP_ENV` from the runtime configuration, the endpoint reads it from the environment.
  Anything but `production` turns it on.
- Without `NG_PUBLIC_APP_ENV` both sides stay off (the browser part only runs in dev mode, the endpoint answers 404).
  Set `NG_PUBLIC_APP_ENV=local` locally.
- `NG_PUBLIC_LT_BUG_ENABLED` switches both sides per stage without a rebuild.
- `NG_PUBLIC_LT_BUG_AUTO_SHOW`, `…_AUTO_OPEN_ON_ERROR`, `…_ENABLE_SCREENSHOT`, `…_POSITION`, `…_BUTTON_COLOR` and
  `…_BUTTON_TEXT` adjust the browser part.

`LtBugReportService.open()` opens the dialog from your own code, `reportError()` reports an error by hand. The app's
`ErrorHandler` is wrapped, so it keeps handling every error.

## What is never recorded

Before sending, and again on the server before Linear:

- `Authorization`, `Cookie`, `Set-Cookie`, `X-System-Setup-Token` and similar headers become `[redacted]`.
- Bodies of `/iam/`, `/system-setup/` and other auth endpoints are never recorded.
- `token`, `code`, `password`, `secret`, `otp` and similar values are redacted in every URL, console line and journey
  entry.
- Password, one-time-code and card fields are never recorded, not even with `captureInputValues`.

The endpoint accepts attachments only as base64 data URLs, validates and caps the body, and limits the rate. Its
answers never contain the API key or Linear's error messages.
