An app uses ng-base in one of two modes:

- **npm mode** (default): `@lenne.tech/ng-base` is a dependency, pinned exactly.
- **vendor mode**: the library is copied into the app as `src/core/`, without an npm dependency. `src/core/VENDOR.md`
  marks the mode and records the baseline and every local change.

## What the CLI does

`lt fullstack init --frontend angular` (with vendor mode) and `lt fullstack convert-mode` copy `projects/ng-base/` of
this repository into `projects/app/src/core/`, without specs, `test-setup.ts`, the library's `package.json`, tsconfigs,
README and CLAUDE.md. Every `ng-package.json` stays: the CLI derives one `tsconfig` `paths` entry per entry point from
its `lib.entryFile`:

| Import                           | Resolves to                             |
| -------------------------------- | --------------------------------------- |
| `@lenne.tech/ng-base`            | `src/core/src/public-api.ts`            |
| `@lenne.tech/ng-base/auth`       | `src/core/auth/src/public-api.ts`       |
| `@lenne.tech/ng-base/ui/provide` | `src/core/ui/provide/src/public-api.ts` |

Imports therefore look the same in both modes. Never import `src/core/…` with a relative path. Stylesheet imports of the
theme are rewritten to the vendored path, because Tailwind resolves CSS imports from `node_modules` only:

```css
@import './core/ui/styles/theme.css';
```

## Changing the vendored core

`src/core/` mirrors upstream. Change it only for something every app needs (a bug fix, a security fix, a general
improvement), record the change in `VENDOR.md` and send it upstream to
[lenneTech/ng-base](https://github.com/lenneTech/ng-base), so it disappears from the local copy with the next sync.
Project code stays outside `src/core/`.

The lenne.tech Claude Code plugin has commands for both directions: syncing a vendored core from upstream, and
preparing local changes as upstream pull requests.
