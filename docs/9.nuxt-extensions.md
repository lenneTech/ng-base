ng-base follows [nuxt-extensions](https://github.com/lenneTech/nuxt-extensions) release for release. Behaviour that is
the same in both is not listed here: 2FA and passkey sign-in never expose the session token, one auth fetch with JWT
renewal, file URLs on the API, TUS on `/tus`, no `/iam/token` against an API that reports `jwt: false`, and so on.

What differs on purpose:

- **Auth state only in `LtAuthService`.** `getClient()` is the stateless Better Auth client. It removes an opaque
  session token from every answer, but never stores a JWT. Make 2FA and password calls through `LtAuthService`, which
  keeps the session in place.
- **`inject…()` instead of composables.** Per-call state comes from factories bound to the injection context
  (`injectLtTusUpload()`, `injectLtAiChat()`, `injectLtOfflineSync()`); shared state lives in root services.
- **SSR calls are anonymous**, `fetchWithAuth` included. nuxt-extensions sends the request's `lt-jwt-token` as bearer
  during SSR. See [Working with nest-server](./4.nest-server.md#ssr-backend-calls-are-anonymous).
- **Transitions** use Angular's `animate.enter` / `animate.leave` with CSS variables for the durations, not Tailwind
  duration utilities.
- **nest-server's JWT mode** (`cookies: false`) works end to end, see
  [Authentication](./3.authentication.md#cookie-and-jwt-mode).
- **Passkeys work without `@better-auth/passkey`**: the WebAuthn calls go straight to `/iam/passkey/*`. The plugin can
  still be passed through `provideLtAuth({ plugins })`.
- **Social sign-in** turns relative callback URLs into absolute app URLs (nuxt-extensions passes them on, and Better
  Auth resolves them against the API). `/sign-in/social` gets cookies in JWT mode too, for Better Auth's OAuth `state`
  cookie.
- **Input before hydration is kept.** Angular's first change detection after hydration overwrites typed text, so
  fields are saved before and restored after hydration (`provideLtNgBase({ preHydrationInput })`, on by default). The
  server also blocks the native submit of forms without `action` before hydration, so no password ends up in a GET
  URL.
- **Bug reporter:** compared with bug.lt, `enabled` is decided at runtime and stays off without a stage, auth bodies
  and query tokens are never recorded, and attachments are data URLs only.

The full, current list is in the
[library README](https://github.com/lenneTech/ng-base/blob/main/projects/ng-base/README.md).
