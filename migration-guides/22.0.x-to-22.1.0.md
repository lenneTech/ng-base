# Migration guide: ng-base 22.0.x → 22.1.0

22.1.0 brings ng-base level with `@lenne.tech/nuxt-extensions` 4.0.1. It contains one breaking change: Better Auth's
session token no longer reaches the caller of a passkey or 2FA sign-in (nuxt-extensions 1.26.0, DEV-4082). The MAJOR
digit is the Angular major, so a breaking change ships as a MINOR.

## Overview

| Category             | Details                                                                                                                                                                                                                                  |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Breaking change**  | `LtPasskeyAuthResult` has no `session` any more: `authenticateWithPasskey()` returns `{ success, error?, user? }`.                                                                                                                       |
| **Behaviour change** | `twoFactor.verifyTotp()` / `verifyBackupCode()` (on `LtAuthService` and on `getClient()`) return the answer without Better Auth's opaque session token. A JWT (nest-server with `cookies: false`) stays.                                 |
| **Removed texts**    | `lt.auth.loggingOut`, `lt.auth.sessionExpired`, `lt.error.loadFailed`, `lt.ui.colorMode`, `lt.ui.colorModeDark`, `lt.ui.colorModeLight`, `lt.ui.colorModeSystem`, `lt.ui.datePlaceholder` (no ng-base code used them).                   |
| **Fixed**            | `LtFileService.getFileUrl()` / `getDownloadUrl()` return the URL the browser uses during SSR too, never the server-only `NG_API_URL`.                                                                                                    |
| **Migration effort** | Usually none. Only code that reads `authenticateWithPasskey().session`, reads `data.token` after `verifyTotp()` / `verifyBackupCode()`, or calls `i18n.t()` with one of the removed keys has to change. ng-base-starter does none of it. |

## Why

Better Auth answers `POST /iam/two-factor/verify-totp` and `verify-backup-code` with `{ token, user }`, and
`POST /iam/passkey/verify-authentication` with `{ session, user }`. With cookies on, the token is the **session token**,
the value nest-server keeps in the httpOnly `iam.session_token` cookie. ng-base never stored it, but it handed it to the
caller: a page that saved it (in `localStorage`, in a readable cookie) made the session available to every script on the
page, for its whole lifetime. nest-server 12.6.1 and later remove the token from these bodies on the server side as well;
ng-base drops it either way.

## Steps

1. **Passkey sign-in.** Drop every read of `result.session` after `authenticateWithPasskey()`. The service has already
   put the session in place (cookie session, or JWT mode when the server sent a JWT); `result.user` is the signed-in
   user.

   ```ts
   const result = await this.auth.authenticateWithPasskey();
   if (result.success) {
     await this.router.navigateByUrl('/app'); // no token handling of your own
   }
   ```

2. **2FA verification.** Do not read `result.data.token` after `twoFactor.verifyTotp()` / `verifyBackupCode()` and never
   store a token yourself. `lt-jwt-token` holds a JWT or nothing, and the service manages it.

3. **Texts.** If the app calls `i18n.t()` with one of the removed keys, register the text in the app's own messages
   (`LtI18nService.registerMessages(locale, messages)`), or use an app text.

4. **File links during SSR.** Nothing to do. A page that renders `getFileUrl()` / `getDownloadUrl()` on the server now
   writes the public URL (`NG_PUBLIC_API_URL`, or `/api` behind the dev proxy) into the HTML.
